# Web application architecture

How `web/` is put together. Every feature follows this shape. It is adapted from the
blueprint used in the expresspass web app. Where SkillCert differs (data layer, router,
where schemas come from), this doc says so and says why.

`docs/development-plan.md` and the functional spec are the source of truth for product
rules and phases. This doc covers only the structure of the React app.

Reference implementation: `web/src/features/auth/` (sign-in).

---

## Part 1: The layered feature

### Folder shape

```
src/
  app/                       # composition root, router, signed-in shell
    App.tsx  providers.tsx  router.ts  queryClient.ts
    routes/                  # TanStack Router file routes: gate + render a Container, nothing else
    shell/                   # AppShell (container), AppHeader, AppErrorScreen
    locales/{en,fr}.po
  features/<name>/
    index.ts                 # barrel: re-export ONLY the public entry (container/page)
                             #   plus any hook another feature legitimately needs
    <Name>Provider.tsx       # optional: context composition root + named selector hooks
    api/<name>Api.gen.ts     # GENERATED by Orval from the OpenAPI spec, never edit
    model/                   # headless hooks / pure functions, ZERO JSX, no MUI
    pages/
      <Name>Container.tsx    # owns the query/mutation hooks; maps errors; passes plain props down
      <Name>Page.tsx         # layout + section dispatch only
      <Name>Page.test.tsx    # one behaviour-level test through the real provider
    components/<Group>/      # small single-responsibility units, grouped as the feature needs
    locales/{en,fr}.po       # per-feature Lingui catalog; en is the source locale
  shared/
    api/client.ts            # apiFetch + ApiError (the Orval mutator)
    api/model/               # GENERATED request/response types
    schemas/*.zod.gen.ts     # GENERATED Zod schemas
    i18n/                    # Lingui runtime + AppI18nProvider / useLocale
    lib/                     # makeTheme, defineModePalette, ThemeModeProvider
    components/              # cross-feature UI (LanguageSwitcher, ThemeModeToggle)
    locales/{en,fr}.po
  test/                      # Vitest setup + TestProviders
```

Imports go through the aliases `@app/*`, `@features/*` and `@shared/*`. A feature imports
another feature only through its barrel (`@features/current-user`), never a deep path.

Not every feature needs every folder. `dashboard` has no `api/` and no provider. When a
folder does exist, it means what is described below.

### 1. Container / Provider / Page triad

- **Container** (`pages/<Name>Container.tsx`) is the only place a TanStack Query hook
  (generated `useX` / `useXMutation`) is called.
  - It maps `ApiError` to a translated display string.
  - It handles success side-effects (cache invalidation, navigation).
  - It hands the provider plain values: `saving`, `error`, and `onX` callbacks.
  - Reference: `features/auth/pages/LoginContainer.tsx`.
- **Provider** (`<Name>Provider.tsx`) composes the `model/` hooks and exposes them through
  context. It has no data-layer dependency, so a test drives it with a `vi.fn()`.
- **Page** (`pages/<Name>Page.tsx`) reads a selector hook and lays out the sections. It
  holds no data logic.

The app shell follows the same rule. `app/shell/AppShell.tsx` is the shell's container:
- it owns the current-user query and the sign-out mutation
- it mounts `CurrentUserProvider` once, so `useCurrentUser()` is never null below the gate.

### 2. `model/` = headless state, no JSX

Hooks that own state, split by responsibility, plus pure functions. There are no React
components and no MUI imports.

- Every hook **exports its return-type contract** (`LoginDraft`), so the provider and tests
  type against a name.
- Its docstring says what it owns **and what it doesn't**, e.g. "Knows nothing about the
  API call, error copy, or where to go after sign-in."

### 3. Context + named selector hooks → components take no props

The provider exposes one selector hook for the chrome and one per section:
`useLoginForm()`, `useEmailField()`, `usePasswordField()`. Its context accessor throws
`"<Feature> hooks must be used within a <Name>Provider"`.

Section components take **zero props** and read only their own selector hook. Sections never
talk to each other.

### 4. Small single-responsibility components

- Group components into sub-folders as the feature needs. `auth` uses `Form/` and `Layout/`;
  the names are not a fixed taxonomy.
- Each file stays short and has minimal props. Ideally it has none and reads a selector hook
  instead.
- Each carries its own style-object factory (Part 2 §4).

### 5. Barrels are the public surface, and side-effect-free

`features/auth/index.ts` exports `LoginContainer` and `useLogout` (the shell signs out).
Barrels never read env or run code at import time.

## Part 2: Cross-cutting conventions

### 1. API access: TanStack Query + Orval, split per feature

*Differs from the expresspass blueprint, which uses RTK Query + injectEndpoints.*

- **Source of the client:** the .NET API writes `web/openapi/skillcert.json` on every build.
- **Generation:** `npm run gen` runs Orval, then the route generator. It also runs before
  `dev`, `build`, `typecheck` and `test`.
- **One file per feature:** `orval.config.ts` maps each **API tag** to its owning feature
  and generates `features/<feature>/api/<feature>Api.gen.ts`. Generation **fails on an
  unmapped tag**, so every new endpoint group gets an owner. To add one, put the tag in
  `featureByTag`.
- **Shared types:** request/response types go to `shared/api/model/`.
- **Fetching:** every call goes through `shared/api/client.ts` (`apiFetch`). It sends the
  same-origin auth cookie and throws `ApiError(status, body)` on any non-2xx response. Use
  `isApiError(error, 401, 403)` to branch.
- **Refetch after a change:** done by `queryClient.invalidateQueries` with the generated
  query key (e.g. `getGetCurrentUserQueryKey()`).

All `*.gen.ts` files and `shared/api/model/` are gitignored. CI regenerates them.

### 2. State management

| Kind of state | Where it lives |
| --- | --- |
| Server data | TanStack Query (generated hooks), called only in containers |
| Local UI / form state | `useState` inside `model/` hooks |
| Shared read-only app state | Context: `CurrentUserProvider` / `useCurrentUser()`, `AppI18nProvider` / `useLocale()`, `ThemeModeProvider` / `useThemeMode()` |
| Auth session | The HttpOnly `skillcert.auth` cookie. There is no client auth store; `/api/me` is the truth |
| Theme mode | `ThemeModeProvider`: `useState` + `localStorage`, OS preference as the default |

There is no Redux. Theme mode is in context rather than prop-drilled, because the router sits
between `App` and the header toggle.

### 3. Forms & validation: no form library

- Use controlled MUI inputs wired to `model/` setters, inside one native
  `<form onSubmit noValidate>`. No react-hook-form, no Formik.
- **Schemas** are generated from the OpenAPI spec into
  `shared/schemas/skillcert.zod.gen.ts` (*the blueprint's shared TS package doesn't exist
  here, because the backend is .NET*). The generated schema carries the API's shape.
  Presence and format rules the spec can't express are added by `.extend()` / refinement
  in the feature's `model/` (see `useLoginDraft`).
- **Messages:** Zod messages stay English and are never rendered. The model exposes *which*
  check failed (`FieldProblem = 'required' | 'invalid' | null`), and the component picks the
  translated copy.
- **Error display tiers:**
  - **field:** `error` + `helperText` on the input, shown only once `showErrors` is set by a
    submit attempt. Use `" "` when clear, so the layout doesn't jump.
  - **section:** `FormControl error` + `FormHelperText`.
  - **form:** `<Alert severity="error">` at the top of the form. It shows the container's
    mapped API error; local validation stops the submit before that.

### 4. Styling

- MUI v7. Icons come from `lucide-react` (**not** `@mui/icons-material`), with
  `aria-hidden` when decorative.
- **Theme:** `shared/lib/theme.ts` `makeTheme(mode)` is built entirely from
  `shared/lib/design-tokens.json`. That file is a copy of the SkillCert design system's
  `project/tokens.json` (https://claude.ai/artifact/7AzLQcJz1v5Nk6J3zG7xor); to change a value,
  change it in the design system and replace the file. Read the system's README for usage rules.
  - **Spacing:** the MUI spacing unit is 4px, so `p: 4` is `space-4` (16px). Use only the token
    steps: 1, 2, 3, 4, 6, 8.
  - **Status colours:** `theme.palette.status.<current|expired|notCompetent|pending|notCertified>.{bg,fg}`.
    Always pair a status colour with a label and an icon.
  - **Type:** `h1` page-title, `h2` section-title, `h3` subsection-title, `body1` body,
    `body2` body-sm, `overline` label, plus `code` (competency codes) and `date` (tabular dates).
  - **Also on the theme:** `palette.brandTint`, `palette.lineStrong`, `palette.focus`, and
    `theme.radius.{sm,md,pill}`.
  - **Fonts:** Public Sans and IBM Plex Mono are self-hosted via `@fontsource`; no Google Fonts
    request at runtime.
- **Prefer theme tokens** (`'text.secondary'`, `'divider'`, `'background.default'`).
- **Mode-dependent colour the theme can't express:** use `defineModePalette`
  (`shared/lib/palette.ts`). It takes `{ light, dark }` tables, or a
  `theme => ({ light, dark })` factory, and gives back a `usePalette()` hook. No
  `isDark ? … : …` ternaries.
- **Per-component style objects:** put a `const <name>Styles = () => ({ … })` factory at the
  top of the file and spread its slices into `sx`. The factory takes the palette when the
  component uses one.
- **Compound components** (`<Stepper>` / `<Stepper.Step>`) mirror MUI's APIs where it reads
  well.
- Layouts are phone-first (development plan §1.4).

### 5. i18n (Lingui, English + French)

- **Macros only:** `<Trans>` and `` t`…` `` from `@lingui/react/macro`, and `msg` from
  `@lingui/core/macro` for lazy labels translated with `i18n._(label)` (see `IdentityCard`).
  Never a bare user-facing string.
- **Build:** Vite compiles the macros through `@rolldown/plugin-babel` +
  `@lingui/babel-plugin-lingui-macro`, and `@lingui/vite-plugin` compiles `.po` files on
  import.
- **Catalogs:** one per feature (`features/<name>/locales/{en,fr}.po`), plus `app/` and
  `shared/`; `en` is the source. `shared/i18n/runtime.ts` globs every `/src/**/locales/*.po`,
  so a new feature needs no wiring.
- **Locale state:** `AppI18nProvider` detects the locale (`localStorage.locale` → browser
  language → `en`). It loads all catalogs for that locale, keeps `<html lang>` in sync,
  persists an explicit choice, and renders nothing until the catalogs are loaded.
- **After any copy change:** run `npm run i18n:extract`, then fill `fr.po`. French strings
  are machine-assisted drafts, flagged at the top of each `fr.po` for review.
- **Not localized:** API error bodies (containers map status codes to copy instead), MUI's
  own strings, and the product name "SkillCert".

### 6. Types

- Domain types are `z.infer<>` of a generated schema, or a projection of one; never
  redeclared. Examples: `CurrentUser = z.infer<typeof GetCurrentUserResponse>`,
  `Credentials = z.infer<typeof LoginBody>`.
- Export hook return-type contracts.
- Component props are a local `type Props`.

### 7. Testing

- **One behaviour-level test per feature** at `pages/<Name>Page.test.tsx`.
  - Render the **real** provider, model hooks, section components, and `TestProviders`
    (real `AppI18nProvider` + theme). Only the outbound callbacks (`onLogin`) are `vi.fn()`.
  - Query by role and label; assert outcomes (`onLogin` called with trimmed credentials,
    French heading rendered), not implementation.
- **`model/` hooks** get no isolated unit tests; the page test exercises them.
- **Gates and containers** are covered by the Playwright smoke tests (development plan,
  Phase 0).

Run with `npm test` (Vitest + jsdom + Testing Library).

### 8. Docs live in docstrings

Intent lives in docstrings on the code, not in READMEs under `features/`.
- Every `model/` hook, provider, container and non-obvious component says what it owns, and
  what it doesn't.
- Inline comments mark boundaries, e.g. where Zod's English messages are swapped for
  translated copy.

### 9. App shell and routing

*Differs from the blueprint, which uses react-router with `lazy()`.* SkillCert uses TanStack
Router with file-based routes in `app/routes/`, and **routes stay thin**.

- **Route files only:**
  - validate search params (e.g. the same-origin `redirect` check in `login.tsx`)
  - run gates (`_authenticated.tsx` `beforeLoad`: `ensureQueryData(currentUserQueryOptions())`,
    redirecting to `/login` on 401/403)
  - render a feature container or page.
- **Code-splitting:** automatic, per route (`autoCodeSplitting`).
- **`app/shell/AppShell.tsx`:** the signed-in chrome container (above).
- **`app/shell/AppErrorScreen.tsx`:** the router's default error screen.
- **`app/providers.tsx`:** the composition root, `AppI18nProvider` › `QueryClientProvider` ›
  `ThemeModeProvider` › MUI `ThemeProvider`.

### 10. Lint

`npm run lint` runs `oxlint --deny-warnings`. It skips generated files. Fast-refresh
export rules are off for `app/routes/**` and `*Provider.tsx`, because route files export
`Route` and providers co-locate their selector hooks by design.
